# Product pressure test

Before writing requirements, check:

1. Evidence: What suggests the user actually has this problem?
2. Specificity: Which user or segment is this for?
3. Counterfactual: What do users do today if this does not exist?
4. Scope: What is the smallest useful version?
5. Non-goals: What should not be built yet?
6. Success: What observable behavior means it worked?

If any answer is unknown, either ask the user or record it as an assumption.
