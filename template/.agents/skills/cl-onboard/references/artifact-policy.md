# Artifact policy

Write artifacts only when they reduce future work.

Always keep:

- AGENTS.md
- STRATEGY.md

Write docs/ideation/ when an idea or direction is substantial and the criticism/ranking may be useful later.

Write docs/brainstorms/ when user-facing behavior, scope, success criteria, or Agent behavior needs durable definition before planning.

Write docs/plans/ for non-trivial implementation: multi-file changes, high-risk changes, Agent behavior changes, integrations, migrations, security, reliability, or anything likely to span multiple steps.

Write docs/solutions/ only for durable learnings: non-obvious root causes, repeated failure patterns, project conventions, framework/dependency gotchas, Agent behavior lessons, or user corrections that future agents may repeat.

Write docs/evals/ when Agent behavior changes and examples or pass criteria should survive beyond the chat.

Do not write artifacts for trivial edits, obvious typos, or one-line changes without durable value.
